# Step 3 - 引导用户搭建 PAD 自动刷新工作流（小白逐击版）

> **本文件从 SKILL.md 拆出**（v1.4.0）。SKILL.md 里只留索引，**需要带着用户搭画布时才读本文件**。

> 这一步**不出代码**，PAD 设计器是 GUI 操作，需要用户亲手搭。
> **读者假设为零基础用户**：agent 引导时必须按本节小节顺序逐步给出（一次 1-2 个小节，不要整页甩给用户），每个动作讲清"动作在左侧哪里搜 → 拖到画布哪里 → 双击后每个框填什么"。**禁止**只用一张参数表打发用户（2026-09-10 用户实测反馈：参数表形式难用且不直观）。

---

## 3.0 搭前必读（动手前先讲完这 4 条）

1. **不要"删了重拖"动作**。PAD 删除重拖会给新动作的变量自动加数字后缀（`Files2`、`ExcelInstance2`…），后面引用旧变量名的动作会全部失联（详见 3.5）。搭错动作的第一选择是**双击它改参数**，不是删除重来。
2. **「启动 Excel」必须选"启动新实例"**。选"使用现有的 Excel 进程"时，若目标 Excel 没开着会直接报错。
3. **点运行前，关闭所有目标 Excel**——包括预览窗口、腾讯文档/WPS 里打开的副本，以及**用户自己双击打开的目标文件本身**。文件被占用会导致刷新/保存失败（Excel 会以只读方式打开，刷出来的数据存不回去）。
4. **⚠️ 运行中途不要点 ⏹ 停止**（2026-09-15 实测）：停止只终止流程逻辑，**不会关闭它已经开出来的 Excel**，必留僵尸进程；而且被中断的那一轮后面的文件不会处理（会出现"部分文件刷新了、部分没刷"）。单文件耗时可参考：小文件约 60~90 秒/个（含 15 秒等待），**看起来"没动静"是正常的**。真怀疑卡住，让 agent 查进程判断。

## 3.1 打开设计器并新建流程

- **开始菜单 → Power Automate**（或 `C:\Program Files (x86)\Power Automate Desktop\dotnet\PAD.Designer.exe`），登录工作/学校账号
- 总控中心 → 我的 flows → 新建 → 桌面流，命名：`批量刷新 [folder_name]`（如"批量刷新乐惠收入模块"），进入画布
- **多模块组织**：每个模块建一个子流程（如"批量刷新乐惠收入模块"、"批量刷新新收入模块"），**Main** 里按顺序调用各子流程；**定时调度只挂在 Main 上**（挂错对象会导致只有单个模块被调度）

## 3.2 搭建 7 个动作（逐击指引）

**动作 1｜获取文件夹中的文件**
1. 左侧"操作"搜索框输入：`获取文件夹中的文件`（在"文件夹"分组）
2. 把它拖到画布第一行
3. 双击打开，填写：文件夹 = `[target_folder]`；文件筛选 = `*.xlsm`；包含子文件夹 = 按需勾选
4. 完成标志：第一行出现该动作，末尾有"→ Files"（**记下这个输出变量名**，后面要用）

📷 **参考截图（2026-09-15 用户实机配置）**：`assets/action1-获取文件夹中的文件.png` —— 红框标出 4 个关键位：文件夹路径 / 文件筛选器 `*.xlsm` / 包含子文件夹开关 / 生成的变量 `Files`

**动作 2｜For each（循环）**
1. 搜索框输入：`For each`（在"循环"分组）
2. 拖到动作 1 的**正下方**
3. 双击：迭代 = `%` + 动作 1 的输出变量名 + `%`（默认即 `%Files%`）；当前项变量记住默认 `CurrentItem`
4. 完成标志：画布出现一个"框"，后续动作都要**拖进这个框里**

**动作 3｜启动 Excel**
1. 搜索框输入：`启动 Excel`（在"Excel"分组）
2. 拖到 For each 框**内部第一行**（拖入时框会高亮）
3. 双击：打开文档 = `%CurrentItem%`；使 Excel 可见 = 否；打开为只读 = 否；**启动方式选"启动新实例"**
4. 完成标志：末尾有"→ ExcelInstance"（**记下这个实例变量名**）

📷 **参考截图（2026-09-15 用户实机配置）**：`assets/action3-启动Excel.png` —— 红框标出：文档路径 `%CurrentItem%`、生成的变量 `ExcelInstance`。
> 注：截图里"使实例可见"是**开**的——开或关都能正常跑（用户实测开也通过）。**推荐关**：关掉运行时不弹 Excel 窗口，桌面清爽；反正跑完看数据时文件是关着的。

**动作 4｜运行 Excel 宏**
1. 搜索框输入：`运行 Excel 宏`（"Excel"分组；PAD 界面上动作名就叫「运行 Excel 宏」，2026-09-16 用户实测确认；输入"运行宏"也可能搜到，但认准面板上的名字是「运行 Excel 宏」）
2. 拖到 For each 框内、动作 3 下面
3. 双击：Excel 实例 = 选动作 3 产出的实例名；宏名称 = `RefreshPowerQuery`；宏参数留空

**动作 5｜等待**
- 拖到 For each 框内动作 4 下面；持续时间 = `15` 秒（不要 < 15，Power Query 异步查询没跑完就保存会丢数据）

**动作 6｜保存 Excel**
- 拖到 For each 框内；Excel 实例 = 动作 3 的实例名；保存模式 = **保存文档**

📷 **参考截图**：`assets/action6-保存Excel.png` —— 唯一要确认的是 Excel 实例 = `%ExcelInstance%`

**动作 7｜关闭 Excel**
- 拖到 For each 框内；Excel 实例 = 动作 3 的实例名；关闭前保存文档 = **不保存**（前面已单独保存）

📷 **参考截图**：`assets/action7-关闭Excel.png` —— 红框标出 Excel 实例 = `%ExcelInstance%`；"在关闭 Excel 之前"必须是**不保存文档**

**动作 8｜终止进程（兜底清理，v1.4.1 新增，实测必需）**
1. 搜索框输入：`终止进程`（在"系统"分组）
2. 拖到 For each 框内、**动作 7 的正下方**（循环内最后一行）
3. 双击：指定进程的依据 = **按名称**；进程名称 = **`EXCEL`**（不用带 .exe）；发给用户 = 关
4. 为什么必需：PAD 的「关闭 Excel」只关掉工作簿，**Excel 程序进程会残留成"空白 Excel 窗口"**（隐身启动 + 插件影响，2026-09-15 实测：一次干净的 2 文件运行漏 3 个壳）。残留进程会锁住文件、导致下次运行报"文件被占用"
5. ⚠️ 副作用：会把电脑上**所有** Excel 结束掉。因此运行期间用户不要自己开 Excel 干活（定时运行时用户不在操作，无影响）

## 3.3 运行前 30 秒自检清单（全部打勾再点 ▶）

- [ ] 动作 1 的输出变量名 == 动作 2 迭代框里写的变量名（打开 For each 核对）
- [ ] 动作 3 文档路径里的 `%...%` == 动作 2 的"当前项变量名"
- [ ] 动作 3 产出的实例变量名 == 动作 4、6、7 引用的实例名（**3 处必须一致**）
- [ ] 动作 5、6、7、8 都在 For each 框**内部**（画布上看得到包含关系）
- [ ] 动作 8「终止进程」进程名称 = `EXCEL`
- [ ] 所有目标 Excel 已全部关闭（含用户自己双击打开的目标文件）

## 3.4 测试运行 + 截图复核

- agent 必须要求：**用户搭完先发画布截图，agent 逐动作复核变量引用后再让用户点 ▶ 测试**（人在回路，避免带病运行）

- 跑的过程用户如果手动打开了目标 `.xlsm`，会锁住文件——**先关掉再跑**，要看数据等跑完再看

## 3.5 关键变量命名（拼写杀手 + 后缀漂移）

| 错误拼写 | 正确拼写 | 影响 |
|---|---|---|
| `Excellnstance`（双 l + 小写 i） | `ExcelInstance`（双 l + 大写 I） | 引用变量会报错，调试费时 |
| 把 `ExcelInstance` 放在 For each 外部 | 放在 For each **内部** | 每次循环都要新建实例，否则只刷第一个文件 |

> ⚠️ **变量后缀漂移（2026-09-10 实战踩坑，最常见的失败原因）**：用户删除重拖任何产出变量的动作（获取文件 / For each / 启动 Excel）后，PAD 会自动生成带数字后缀的**新**变量（`Files2`、`CurrentItem2`、`ExcelInstance2`），而**后面的动作仍引用旧变量名**——运行时不报搭建错误，但循环取不到文件/实例。agent 引导搭建后必须提醒：
> 1. 搭完后按 3.3 清单逐个检查变量引用，确保**全链路一致**（以动作 1/3 实际产出的变量名为准，后缀是几就统一用几；名字本身叫什么不重要）；
> 2. 若用户重搭过动作，优先让用户改下游动作的引用（或在右侧"变量"面板重命名，重命名会自动同步引用），而不是再删重拖（越删后缀越大）；
> 3. 「启动 Excel」动作必须选**启动新实例**，不能选「使用现有的 Excel 进程」——目标 Excel 没开着时直接报错，且实例变量不会绑定。

## 3.6 （可选加速）整段粘贴动作序列

PAD 支持把动作以文本形式复制/粘贴到画布（Robin 脚本格式，`@@coffee:` 开头），粘贴后自动还原成完整动作。**但语法与 PAD 版本/界面语言相关，不要凭记忆硬写**，按以下校准流程操作：

1. 让用户按 3.2 手搭**动作 1**（获取文件夹中的文件）这一个动作
2. 右键该动作 → 复制，把剪贴板文本粘贴发给 agent
3. agent 照该语法生成其余动作的文本，用户全选复制 → 画布中点击 → Ctrl+V 粘贴，再把粘贴出的动作按顺序拖入 For each 框
4. **粘贴无反应/报错时，直接回退 3.2 逐击指引**，不要反复尝试
5. ⚠️ **动作 8「终止进程」建议手拖**（就一个动作，10 秒的事）——`终止进程` 的 Robin 语法未经校准，别硬写。**粘贴后必须逐条核对 3.3 清单**：粘贴出来的动作可能缺"终止进程"，或变量名带后缀

## 3.8 运行约束

- ✅ 运行 PAD 时**关闭所有目标 Excel**（文件占用会导致保存失败）
- ✅ `target_folder` 路径固定后**不要改动**
- ✅ 等待秒数不要小于 15（太短导致 Power Query 异步查询未完成就保存）
- ✅ 如果 Excel 文件经常有变动，考虑把等待调到 30 秒

## 3.9 跑完之后：怎么确认真的刷新成功了（v1.4.0 新增）

> **点完 ▶ 不等于成功。** PAD 的每一步都可能"显示绿色"，但数据其实没刷新——
> 最常见的原因是等待时间太短，Power Query 还没跑完就保存了。
> 按下面 4 步验，1 分钟能确认。

### 第 1 步：看 PAD 有没有报错

- PAD 运行结束后会显示运行结果。**任何一步是红叉就别往下走**，先看它报在哪一步
- 常见报错与对策：

| PAD 报的错 | 说明 | 怎么办 |
|---|---|---|
| 找不到 `RefreshPowerQuery` 宏 | 宏没注进去，或名字对不上 | 回 Step 2 重新注入宏，并复核模块名 |
| 文件被占用 / 无法保存 | 有 Excel 没关干净 | 关掉所有 Excel（含预览、WPS）再跑 |
| 找不到文件 | 文件夹路径变了，或筛选条件写错 | 核对动作 1 的文件夹与筛选（应为 `*.xlsm`） |
| 找不到 Excel 实例 | 动作 3 选了"使用现有的 Excel 进程" | 双击动作 3 改成"启动新实例" |

### 第 2 步：看文件时间戳变没变（最快，不用打开表）

```powershell
Get-ChildItem "<target_folder>" -Filter '*.xlsm' -File |
    Select-Object Name, LastWriteTime |
    Format-Table -AutoSize | Out-String -Width 200
```

- **看 `LastWriteTime` 是不是刚刚**。如果还停在几天前，说明"保存"那步没生效
- 想更直观：跑之前先执行一次同样的命令记下时间，跑完再比一次

### 第 3 步：抽一张表打开看数据

- 打开任意一个 `.xlsm` → 看 Power Query 出来的那张表，**数据日期 / 数字是不是变新了**
- 顺手确认宏还在：按 `Alt+F11` 打开 VBA 编辑器，左侧模块列表里应能看到 `RefreshModule`

### 第 4 步：检查 Excel 进程有没有残留（v1.4.1 新增）

**为什么必做**：PAD 的「关闭 Excel」只关工作簿，**Excel 程序进程会残留成"看不到的空白 Excel"**——会锁住文件，害下一次运行报"文件被占用"。判据：**运行结束后 Excel 进程数应为 0**（用户运行前已按 3.0 第 3 条关掉所有 Excel）。

```powershell
# 查看残留（只读，安全）
Get-Process EXCEL -ErrorAction SilentlyContinue |
    Select-Object Id, MainWindowTitle, StartTime |
    Format-Table -AutoSize | Out-String -Width 200
```

- **返回空 = 干净** ✅；有输出（且 `MainWindowTitle` 多为空）= 有僵尸壳
- 若已按动作 8 配好「终止进程」却仍有残留，检查三点：动作 8 是否在 For each 框**内部**、进程名称是否 `EXCEL`、是否运行中途点过 ⏹

**清理残留（需用户确认后执行）**：只杀**没有窗口标题**的进程，保留用户正在用的可见窗口

```powershell
foreach ($x in @(Get-Process EXCEL -ErrorAction SilentlyContinue)) {
    if ([string]::IsNullOrWhiteSpace($x.MainWindowTitle)) { Stop-Process -Id $x.Id -Force }
}
```

### 时间戳没变时的排查顺序

| 最可能的原因 | 怎么确认 | 怎么修 |
|---|---|---|
| 等待时间太短，PQ 没跑完就保存了 | 这是**第一大原因**，先查这个 | 把动作 5 的等待从 15 秒调到 30 秒，重跑 |
| 文件被占用 | 看目标文件夹里有没有 `~$` 开头的锁文件 | 关掉所有 Excel 再跑 |
| 宏根本没跑起来 | 看 PAD 运行日志里"运行 Excel 宏"那一步 | 回 Step 2 用 COM 复核模块（见 SKILL.md Step 2.6） |
| 数据源本身没更新 | 在 Excel 里手动点一次"全部刷新"试试 | 那属于数据源的问题，不是本流程的问题 |
| **部分文件没刷新**（有的变了有的没变） | 回想运行中途是否点过 ⏹，或是否手动打开过某个目标文件 | 中途停止会跳过后续文件；手动打开会锁文件。关掉 Excel，完整重跑一次（见 3.0 第 3、4 条） |
